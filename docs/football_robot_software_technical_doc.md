# football_robot 软件技术路线说明

## 1. 系统定位

`football_robot` 是面向足球机器人任务构建的软件系统，核心目标不是单一实现“能动”或“能夹”，而是完成从目标感知、运动决策、底盘执行到机构收球的全流程闭环控制。

该系统围绕比赛场景中的真实需求进行设计，已经形成一套完整的软件技术路线：

- 以前端视觉识别完成足球目标检测与相对位姿估计
- 以惯性传感和底盘运动学模型完成稳定机动控制
- 以任务状态机完成对准、接近、拾取等动作编排
- 以气动执行机构完成最终收球动作闭环

因此，`football_robot` 并不是传统意义上的“遥控车程序”，而是一套具备感知、决策、控制、执行四层协同能力的足球机器人软件方案。

## 2. 总体技术架构

整套系统采用分层式架构组织，强调模块清晰、链路稳定、控制实时。

### 2.1 感知层

感知层负责获取足球目标信息，并将图像信息转换为可用于控制的结构化数据。其核心能力包括：

- 对比赛用足球进行稳定识别
- 提取目标在图像中的中心位置、面积和边界信息
- 根据目标成像特征估计足球与机器人之间的相对距离
- 判断目标相对机器人当前视场的左右偏差

这一层的本质，是把“看见球”转化为“知道球在哪里、离自己多远、偏了多少”的控制输入。

### 2.2 决策层

决策层负责将目标信息转化为运动策略。系统不是简单地朝目标方向直接冲刺，而是基于目标偏差和距离信息，对动作进行分阶段组织：

- 当目标横向偏差较大时，优先执行横向修正
- 当目标基本对正后，切换为前向接近
- 当目标进入机构有效作用范围后，触发拾取动作
- 在动作切换过程中持续监测目标状态，保证路径和机构配合稳定

这种处理方式体现的不是单步响应，而是面向任务完成的闭环决策逻辑。

更关键的是，决策层直接建立了视觉量到控制量的映射关系。视觉模块输出的目标中心偏移、目标尺度变化和距离估计结果，不会停留在识别层，而是被实时转换为底盘的横移指令、前进指令和微调转向指令。也就是说，图像中的“球偏左、球偏远、球已进入拾取窗口”等判断，会在同一控制周期内被翻译成明确的运动动作。

### 2.3 控制层

控制层承担运动指令落地，是整套系统技术含量的核心之一。当前底盘采用支持前进、横移、转向的全向机动方案，能够在有限场地内完成高灵活度调整。软件侧围绕这一底盘特性，建立了对应的控制链路：

- 根据控制目标生成底盘速度指令
- 对左右驱动与中置横移通道进行协同输出
- 结合惯性传感器信息保证姿态感知一致性
- 通过输出限制与节奏控制抑制瞬时冲击，提高动作稳定性

这意味着机器人在接近足球时，不是依靠粗放式碰运气动作完成对准，而是依靠可控的横向平移、前向推进与姿态调整完成精确接球。

在这一层中，视觉并不是一个旁路模块，而是控制前端的一部分。控制系统持续接收视觉测得的横向误差和距离误差，并将其分别分配到横移通道和前进通道；当姿态偏差需要抑制时，再由转向通道进行小幅修正。三类控制量并行工作，使机器人在靠近足球的整个过程中始终保持“边修正、边接近、边稳定”的动态控制状态。

### 2.4 执行层

执行层由气动机构完成最终收球动作。软件对该机构的控制不是孤立存在，而是嵌入整套任务闭环中：

- 依据目标距离与位置关系确定触发时机
- 在机器人到达有效收球窗口后执行开合动作
- 保证底盘接近动作与机构动作之间的先后关系清晰

执行层的价值在于把前面的感知、决策与控制成果，最终转化为可验证的任务结果。

## 3. 核心技术路线

系统的核心技术路线可以概括为：

`目标识别 -> 相对定位 -> 横向对正 -> 前向接近 -> 机构收球 -> 状态确认`

从工程实现角度看，这条路线包含以下几个关键技术点。

### 3.1 视觉目标识别与信息提取

系统首先通过视觉模块识别足球目标，并提取目标在图像坐标系中的位置特征。这里输出的不是简单的“有球/没球”结果，而是面向控制的连续信息，包括：

- 目标中心点位置
- 目标轮廓尺寸
- 目标相对视场偏移量
- 目标距离估计结果

这一步决定了后续控制是否具备足够的方向性和精度，是整套系统由“被动操控”迈向“自主处理”的基础。

### 3.2 相对位姿估计与目标对正

在获得视觉信息后，系统将足球目标映射为机器人坐标系下的相对位置描述。软件重点处理两个量：

- 横向偏差
- 前向距离

横向偏差用于指导机器人左右平移或调整姿态，使足球逐步进入最佳拾取通道；前向距离用于控制推进节奏，避免靠近过快导致冲撞、漏夹或姿态破坏。

这种处理机制使机器人具备“先校正、后接近”的动作逻辑，而不是把识别结果直接粗暴映射为电机输出。

在具体联动中，视觉模块会稳定输出三类核心控制信息：

- 图像中心偏差，用于表征足球相对机构中心线的左右偏移
- 目标尺度与距离估计，用于判断当前接近阶段和前进节奏
- 目标连续性信息，用于判断识别是否稳定、是否允许继续推进

这三类信息共同决定控制层当前应优先修正什么、抑制什么、触发什么，而不是只依赖单一坐标值做瞬时响应。

### 3.3 视觉与控制的闭环联动机制

视觉与控制之间的联动，采用的是连续闭环而非一次性触发机制。其核心流程如下：

`图像采集 -> 目标识别 -> 偏差计算 -> 控制分配 -> 底盘执行 -> 新一帧反馈`

在每一个控制周期内，系统都会完成以下动作：

- 从当前图像中提取足球中心位置和目标尺度
- 计算足球相对图像中心的横向误差
- 结合目标尺度变化估计前向距离误差
- 将横向误差映射为底盘横移输出
- 将距离误差映射为底盘前进输出
- 将姿态残余误差映射为小幅转向修正
- 在输出限制后下发到底盘，进入下一帧观测

这意味着机器人并不是“看见一次球，执行一次动作”，而是在运动过程中不断根据新画面重新修正轨迹。视觉每刷新一次，控制目标就同步更新一次，底盘输出也随之细调一次，因此机器人能够在目标位置持续变化的情况下仍然保持稳定逼近。

从控制策略上看，系统采用优先级明确的联动方式：

- 当横向误差较大时，横移控制占主导，前进速度被主动压低
- 当横向误差收敛到拾取通道附近时，前进控制逐步提升，占据主导
- 当目标已进入近距离区域时，控制重点从快速接近切换为精细压距
- 当目标进入机构有效窗口后，底盘推进受控收敛，机构动作被同步触发

这种优先级切换机制保证了视觉修正不会被前进动作“顶穿”，也保证了机器人不会在未对正时盲目前冲。

为了保证联动稳定性，系统还对视觉结果做了控制化处理，而不是直接将原始识别结果映射为电机输出。具体表现为：

- 对目标位置变化采用连续帧一致性约束，抑制单帧跳变带来的误动作
- 对距离变化采用平滑节奏控制，避免因尺度突变导致前冲过猛
- 对目标短时遮挡或边缘识别波动采用保守控制策略，优先维持姿态稳定
- 对临近收球阶段的控制输出进行主动收敛，保证机构动作窗口稳定

因此，视觉模块提供的是可控、可解释、可连续消费的状态量，控制模块消费的是经过筛选和约束后的有效误差，而不是噪声化的原始图像结果。

### 3.4 全向底盘精细控制

`football_robot` 的底盘软件建立在多通道联合控制之上，能够同时管理：

- 左侧驱动输出
- 右侧驱动输出
- 中置横移输出

该结构使机器人天然具备三类能力：

- 前后机动
- 左右平移
- 原地转向

对足球拾取任务而言，这种底盘形态具有明显优势。机器人无需大范围绕行即可完成对球修正，能够直接通过横移把机构中心线对准目标，从而降低路径复杂度，提高动作效率。

### 3.5 惯导参与的稳定控制

系统启动后会对惯性传感器进行校准，并重置航向与旋转量，使机器人在运行开始前建立统一姿态参考。惯导数据的引入，使系统在运动控制中具备稳定的方向感知基础，有利于：

- 保持控制输入与车体姿态之间的一致性
- 降低快速变向时的姿态漂移影响
- 为对正、接近和动作切换提供稳定参考

这类姿态基准能力，是机器人从“可运动”提升到“可精控”的关键组成部分。

### 3.6 输出整形与动作稳定性设计

系统在底盘控制中加入了输出限制机制，对左右驱动和横移通道的综合输出进行约束。其意义不只是“限速”，而是在任务执行层面实现：

- 降低瞬时大幅加减速带来的冲击
- 提高调姿与对球时的可控性
- 让视觉修正和底盘响应更容易形成稳定闭环

对于足球机器人这类需要边移动边对准的系统而言，控制输出是否平顺，直接决定了识别结果能否被有效转化为动作结果。

### 3.7 收球机构联动控制

在底盘把足球送入有效工作区域后，系统触发气动机构完成收球。这里的关键不在于单纯控制一次开合，而在于将其纳入时序联动逻辑：

- 先完成目标对正
- 再完成距离压缩
- 最后执行机构动作

这一处理方式避免了机构提前动作或无效动作，使拾球动作具备明确的软件判据和控制节奏。

在视觉与控制深度联动的框架下，机构触发并不是孤立事件，而是前级控制链路自然收束后的结果。只有当视觉确认目标处于中心窗口、控制确认底盘速度已收敛、距离确认达到有效拾取区间后，系统才执行机构动作。这样形成的是“视觉确认位置、控制确认状态、机构完成闭环”的三级联动，而不是简单的按条件开关气缸。

## 4. 软件实现特点

从现有软件结构看，`football_robot` 已经具备较强的工程化组织能力。

### 4.1 模块化硬件封装

机器人硬件对象被统一封装在 `RobotHardware` 中，集中管理：

- 主控与手柄
- 惯性传感器
- 底盘对象
- 气动执行机构

这种封装方式保证硬件接口清晰、初始化流程统一，也便于后续进行多机器人或多任务场景复用。

### 4.2 状态与控制解耦

系统通过独立的状态对象维护控制输入和执行机构状态，使感知、控制、执行之间的关系更清晰，避免逻辑直接堆叠在主流程中。这种设计体现出明显的软件工程意识，便于后续扩展复杂任务状态机。

### 4.3 比赛流程适配

软件已按照竞赛机器人运行机制组织为初始化、自动阶段、手动阶段等标准入口，说明整套系统不是演示性质程序，而是按正式比赛环境构建的控制软件。

### 4.4 实时循环控制

系统采用固定刷新周期运行控制循环，持续更新输入、底盘输出和机构状态。这保证了运动控制具有实时性，也为视觉输入接入后的闭环调节提供了稳定的软件运行节拍。

## 5. 技术价值总结

`football_robot` 的技术价值，不体现在某一个孤立模块，而体现在多模块协同形成的完整能力闭环：

- 视觉模块负责把环境目标转化为结构化控制信息
- 决策模块负责把目标信息组织为分阶段动作策略
- 底盘控制模块负责将策略稳定地映射为精细运动
- 执行机构负责将运动成果转化为最终收球结果

这套技术路线本质上是一种典型的智能机器人任务闭环方案。它覆盖了目标感知、相对定位、路径修正、运动控制、执行联动等多个关键技术环节，具备较高的系统集成度和明确的工程实现价值。

从比赛应用视角看，该软件方案已经形成了足球机器人最核心的能力框架：看得见、算得准、移得稳、收得住。其优势不只是实现功能，更在于能够以较强的稳定性、可解释性和工程组织能力完成整套动作链条。
